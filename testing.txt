

# Final Comprehensive Testing Guide for MERN Backend

## 1. Auth Routes

### Signup (Register User)

- **Method:** POST  
- **URL:** `/api/auth/signup`  
- **Headers:**  
  `Content-Type: application/json`  
- **Body (JSON):**
  ```json
  {
    "name": "John Doe",
    "email": "john@example.com",
    "password": "YourPassword123",
    "role": "user"  // optional, defaults to "user" if omitted
  }
  ```
- **Expected:**  
  - Status 201 (Created)  
  - JSON response with user (name, email, role) and JWT token (no password)

### Login

- **Method:** POST  
- **URL:** `/api/auth/login`  
- **Headers:**  
  `Content-Type: application/json`  
- **Body (JSON):**
  ```json
  {
    "email": "john@example.com",
    "password": "YourPassword123"
  }
  ```
- **Expected:**  
  - Status 200  
  - JSON response with user info and JWT token.

## 2. Product Routes

### Get All Products

- **Method:** GET  
- **URL:** `/api/products`  
- **Headers:** None required  
- **Expected:** Array of products

### Create Product (Requires JWT Authorization)

- **Method:** POST  
- **URL:** `/api/products`  
- **Headers:**  
  - `Content-Type: application/json`  
  - `Authorization: Bearer `  
- **Body (JSON):**
  ```json
  {
    "title": "Sneakers",
    "desc": "Light running shoes",
    "price": 59.99,
    "stock": 100,
    "category": "footwear"
  }
  ```
- **Expected:**  
  - Status 201   
  - JSON product object (with all created fields)

### Get Single Product by ID

- **Method:** GET  
- **URL:** `/api/products/`  
- **Headers:** None required

### Update Product by ID (Requires JWT)

- **Method:** PUT  
- **URL:** `/api/products/`  
- **Headers:**  
  - `Content-Type: application/json`  
  - `Authorization: Bearer `  
- **Body (JSON):** *(Example: partial or full update)*
  ```json
  {
    "price": 49.99,
    "stock": 80
  }
  ```

### Delete Product by ID (Requires JWT)

- **Method:** DELETE  
- **URL:** `/api/products/`  
- **Headers:**  
  `Authorization: Bearer `

## 3. Cart Routes (All Require JWT)

### Get Cart

- **Method:** GET  
- **URL:** `/api/cart`  
- **Headers:**  
  `Authorization: Bearer `  
- **Expected:** Cart object with populated products

### Add to Cart

- **Method:** POST  
- **URL:** `/api/cart/add`  
- **Headers:**  
  - `Content-Type: application/json`  
  - `Authorization: Bearer `  
- **Body (JSON):**
  ```json
  {
    "productId": "PUT_VALID_PRODUCT_ID_HERE",
    "quantity": 2
  }
  ```
- **Expected:** Updated cart object with the product added or quantity increased.

### Remove from Cart

- **Method:** POST  
- **URL:** `/api/cart/remove`  
- **Headers:**  
  - `Content-Type: application/json`  
  - `Authorization: Bearer `  
- **Body (JSON):**  
  *Based on your final schema, you **must send both** `productId` and `quantity` unless you adapted the schema otherwise.*

  Example with quantity (if your schema requires it):
  ```json
  {
    "productId": "PUT_VALID_PRODUCT_ID_HERE",
    "quantity": 1
  }
  ```
  OR if you adjusted the schema to make quantity optional for removal, this is enough:
  ```json
  {
    "productId": "PUT_VALID_PRODUCT_ID_HERE"
  }
  ```
- **Expected:** Updated cart object with that product removed.

## 4. Order Routes (All Require JWT)

### Place Order

- **Method:** POST  
- **URL:** `/api/orders`  
- **Headers:**  
  - `Content-Type: application/json`  
  - `Authorization: Bearer `  
- **Body (JSON):**  
  Your order schema expects a confirm boolean, example:
  ```json
  {
    "confirm": true
  }
  ```
- **Expected:** New order object, cart emptied.

### Get All Orders (Order History)

- **Method:** GET  
- **URL:** `/api/orders`  
- **Headers:**  
  `Authorization: Bearer `

# General Testing Tips:

- Always **copy the JWT token** from login/signup responses and paste it in the Authorization header as `Bearer ` for all protected routes.
- For product and cart routes requiring IDs, **get valid IDs** by listing products or fetching your cart before testing.
- Use tools like **Postman** or **curl** to send these requests.
- When you receive validation errors, check that you send all required fields exactly as per the validation schema.
- If errors occur, look at the **server console logs** for details and also the JSON error messages in response for clues.
